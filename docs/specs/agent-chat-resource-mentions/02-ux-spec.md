# Agent Chat 资源 `@` 引用 + 多选 Pick（UX Spec）

> FEATURE_SLUG: `agent-chat-resource-mentions`
> 前置：`01-feature-spec.md`

## 1. 心智模型

用户在 Agent Chat 中输入消息时，有两条并行通道：

1. 文本通道：自然语言说明需求。
2. 资源通道：通过 `@` 引用结构化资源，再按需绑定图片。

最终发送时，用户看到的仍是文本消息；结构化引用作为执行上下文增强。

## 2. 输入交互

### 2.1 `@` 候选触发

1. 在输入框中输入 `@`，弹出候选层。
2. 候选按分组显示：`项目` -> `场景` -> `模特` -> `图片`。
3. 输入更多字符实时过滤（防抖）。
4. 无结果时显示空状态“未找到可引用资源”。

### 2.2 键盘行为

1. `↑/↓`：移动高亮项。
2. `Enter`：候选打开时确认当前项；候选关闭时执行发送。
3. `Esc`：关闭候选；若已关闭且在 streaming 中，触发打断（保持现有语义）。
4. `Shift+Enter`：换行。

### 2.3 mention token 展示

1. 插入后在输入框高亮显示 token。
2. token 删除时触发绑定清理。
3. 同一消息可出现多个 token。

## 3. Pick 多选交互

### 3.1 进入方式

1. 选中 mention 后，在输入区下方显示“Pick 图片”入口。
2. 点击入口打开对话层（modal/sheet 均可，首期用 dialog）。

### 3.2 面板能力

1. 图片网格：支持缩略图预览。
2. 多选：点击卡片切换选中态。
3. 批量动作：`反选`、`清空`。
4. 确认后回写到 mention 绑定。

### 3.3 状态设计

1. Empty：资源无图片可选，提供“仅引用资源发送”。
2. Loading：骨架屏或 spinner。
3. Error：展示错误提示与“重试”。

## 4. 发送与反馈

1. 普通发送：与现有体验一致，仅新增 mentions 透传。
2. steer/follow-up：沿用现有按钮语义，附带 mentions。
3. 降级时不弹阻断弹窗，必要时显示轻提示（toast/inline）。
4. 乐观消息继续展示 plain text，不展示结构化元数据。

## 5. 边界场景

1. 资源被删除：发送时自动降级丢弃该 mention。
2. 图片失效：仅丢弃失效图片，其它有效图片保留。
3. 全部 mention 失效：整条消息按纯文本发送。
4. 编辑 token：重新解析 mentionId 与绑定；无效绑定自动回收。

## 6. 可访问性与可用性

1. 候选列表有明确 active 样式。
2. 关键按钮（Pick、清空、确认）有可读 label。
3. 鼠标与键盘都可完成完整流程。
4. 移动/窄屏下候选层与 Pick 面板不遮挡发送主按钮。

## 7. 验收清单（UX）

1. `@` 到插入 token 的路径不超过 3 次按键（输入后上下+Enter）。
2. Pick 多选可在 10 张图内流畅操作（含反选/清空）。
3. Enter 发送与候选确认无冲突。
4. 降级策略对用户可感知为“可继续发送”。
