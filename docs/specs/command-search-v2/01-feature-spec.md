# Command Search V2 - Feature Spec

## 背景与目标

- 背景：
  - 项目已移除模块内搜索栏，当前全局搜索（Command Search）成为唯一检索入口。
  - 现有实现可用但信息架构混乱：结果分组重叠、范围（Scope）推断不稳定、实体覆盖不完整（缺模特资产）。
- 目标（用户价值）：
  - 提供一个稳定、可预期、键盘优先的全局搜索入口，覆盖“找对象 + 做动作 + 跳转页面”。
  - 与当前页面上下文联动，默认给出最相关结果，减少用户切页与重复操作。
- 非目标（明确不做）：
  - 不做语义向量检索、不接入远端搜索服务。
  - 不在 V2 引入复杂自然语言意图解析（如“帮我新建一个包含 3 套 look 的项目”）。

## 用户故事 / 使用场景

- 作为摄影工作流操作者，我希望按 `⌘K` 后直接找到目标项目/场景/模特并跳转到对应对象，以便减少层级导航成本。
- 作为高频用户，我希望无输入时看到“最近继续工作”与“常用动作”，以便快速恢复上下文。
- 作为在项目详情页中的用户，我希望搜索默认带项目范围，以便避免跨项目结果干扰。

## 交互与流程

- 入口：
  - 顶部 Toolbar 搜索按钮
  - 全局快捷键 `⌘K` / `Ctrl+K`
- 主流程（分步骤）：
  1. 打开 Command Search，对话框聚焦输入框。
  2. 系统根据当前路由与 URL search 自动推断 scope（global / project / assets-scenes / assets-models）。
  3. 无输入时显示：最近继续工作、常用动作。
  4. 输入关键词后，按统一排序规则返回对象结果（项目/场景/模特）与动作结果。
  5. 回车执行高亮项；或方向键选择后回车执行；执行后关闭弹窗。
  6. 对象跳转后落在目标实体（例如项目选中、场景高亮、模特选中）。
- 异常/边界流程：
  - 数据源部分失败：保留可用分组并在分组内提示“加载失败，可重试”。
  - 目标实体被删除：跳转到目标页并提示“对象不存在或已删除”。
  - 无匹配：显示清晰空状态与可执行下一步（新建项目/新建场景/打开模特库）。

## 数据与接口影响

- 新增/修改的数据结构（引用 `docs/engineering/contracts.md`）：
  - 前端新增统一搜索文档模型（建议）：`SearchDocument`，字段至少含 `entityType`、`id`、`title`、`subtitle`、`keywords`、`scopeHints`、`updatedAt`。
  - 保留 `SearchItem` 作为 UI 映射层，避免业务数据直接耦合视图。
- 新增/修改的 API（引用 `docs/engineering/api.md`）：
  - V2 第一阶段不新增后端 API，沿用已有 `getProjects/getSceneAssets/getModelAssets`。
  - 若数据量增长或需跨端一致排序，再评估 `GET /search` 聚合接口（后续版本）。
- 迁移策略（如有历史数据）：
  - 最近访问 localStorage key 可沿用；若结构变更，提供一次性兼容读取与回写。

## 验收标准

- [ ] `⌘K`/`Ctrl+K` 可在主窗口任意页面打开搜索弹窗，输入框自动聚焦。
- [ ] 无输入时可见“最近继续工作 + 常用动作”，且不出现空白页。
- [ ] 输入关键词后，项目/场景/模特均可被检索；结果数量与排序符合规格定义。
- [ ] 在项目上下文页打开时，默认 project scope 生效；清除 scope 后回到全局结果。
- [ ] 选中对象后可跳转并定位到目标实体（而非仅跳到列表页）。
- [ ] 数据源失败时，用户可看到明确报错并可点击重试，不影响其他分组使用。
- [ ] 失败场景（实体不存在、数据拉取超时、无匹配）有可理解提示与下一步动作。

## 风险与回滚

- 风险：
  - 结果排序策略不合理会导致“看起来有结果但总不在前面”。
  - Scope 自动推断错误会显著降低信任度。
  - 搜索与路由跳转耦合不当，可能引入错误选中或状态残留。
- 回滚方案：
  - 保留 V1 分组逻辑与 action 映射；通过 feature flag 在前端快速回退。
  - 出现稳定性问题时先禁用新排序/新 scope，仅保留全局关键词匹配。
